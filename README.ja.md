# namemask

**日本語の機密テキストを、外部AIに投げる前にローカルで仮名化し、応答を元の固有名詞に復元する。**

## なぜ必要か

議事録・顧客メール・契約書ドラフトを ChatGPT / Claude / Gemini に相談したい。
でもそこには取引先の会社名・担当者名・電話番号・住所が入っていて、
そのままではマシンの外に出せない。

namemask はそれらを**ローカルで**仮名化し、外部AIに貼るためのマスク済みテキストを渡し、
AIの応答に含まれるプレースホルダを元の固有名詞に戻す。

```
原文 ──[namemask mask]──> マスク済み ──> 外部AI ──> 応答
                                                    │
原文の固有名詞に復元 <──[namemask unmask]───────────┘
```

**外部通信ゼロ。telemetry なし。namemask 自身が外部AIに送信することはない。**
送信は人間がコピー＆ペーストで行うので、何がマシンから出るかを必ず自分の目で確認できる。

## クイックスタート

```bash
pip install namemask
namemask --version
```

**辞書ファイルもモデルのダウンロードも不要。** 決定的層だけで即座に動く。

マスク済みテキストは stdout（または `-o`）へ、検出レポートと警告は **stderr** へ出るので、
パイプでつないでも出力は汚れない。メッセージは、namemask が対象とするテキストと同じ日本語で出る。

```console
$ cat memo.txt
株式会社サンプル商事の田中様より、新規案件のご連絡。
連絡先は tanaka@example.co.jp、電話 03-1234-5678。

$ namemask mask memo.txt --no-ner --address -o masked.txt
mapping 保存: .session/mapping.json（生の機密。復元後は `unmask --wipe` で破棄推奨）
=== マスク結果: 4 件 ===
  [[組織_1]]      組織      株式会社サンプル商事   <- structural
  [[人名_1]]      人名      田中   <- structural
  [[メール_1]]     メール     tanaka@example.co.jp   <- regex
  [[電話_1]]      電話      03-1234-5678   <- regex
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。

$ cat masked.txt
[[組織_1]]の[[人名_1]]様より、新規案件のご連絡。
連絡先は [[メール_1]]、電話 [[電話_1]]。
```

レポートには、マスクした値と**それを見つけた層**（`structural` / `regex` / `denylist` /
`address` …）が並ぶ。送信前にレビューするのはこの内容である。

`masked.txt` を自分の目で確認してから外部AIへ貼る。応答を保存して:

```console
$ namemask unmask reply.txt -o restored.txt --wipe
mapping 破棄: .session/mapping.json

$ cat restored.txt
株式会社サンプル商事の田中様へ、以下の返信案です。
ご不明点は tanaka@example.co.jp または 03-1234-5678 までご連絡ください。
```

mapping は**カレントディレクトリ配下**の `.session/mapping.json` に書かれ（ファイル `0600` /
ディレクトリ `0700`。パーミッションが実効なのは POSIX で、Windows では ACL の管理下に入る）、
既定では同じ場所から読み戻される。`-m` でパスを変更、
`--no-save` でメモリのみ。`--wipe` は復元後に破棄し、`namemask wipe` はいつでも破棄する。
**mapping には原文の固有名詞がそのまま入っている。生の機密として扱うこと。**
このリポジトリでは `.session/` を `.gitignore` に入れてあるが、自分のリポジトリにも追加すること。

### 最初の実行の前に知っておくべき2つのフラグ

- **`--address` は opt-in。** 付けないと住所・郵便番号は**マスクされない**。
  対象テキストにどちらかが含まれるなら必ず付ける。
- **`--no-ner` は起動時の通知を止める。** CLI は既定で NER 層を試み、`ner` extra が
  未導入だと `NER disabled: spacy import failed (ModuleNotFoundError). Deterministic
  layers remain.` を stderr に出す。これは**エラーではなく fail-safe**（決定的層による
  マスクは残る）だが、NER を使わないと決めているなら `--no-ner` で明示的に飛ばせる。

### 主なオプション

| オプション | 効果 |
|---|---|
| `-o PATH` | マスク済み／復元済みの出力先（省略で stdout） |
| `-m PATH` | mapping のパス（既定: `.session/mapping.json`） |
| `--clients data/clients.csv` | 取引先辞書を使う（登録済みの取引先は recall 100%） |
| `--address` | 住所・郵便番号も検出する（**既定 off**） |
| `--no-ner` | NER 層を使わない（決定的層のみ・高速） |
| `--llm` | ローカル Ollama の検証パスを後段に付ける（**追加専用**） |
| `--html report.html` | レビュー用の単一HTMLを出力（外部CDN・外部JS不使用・`0600`） |
| `--encrypt` | mapping を AES 認証暗号で保存（`NAMEMASK_PASSPHRASE` が必要） |
| `--no-save` | mapping をファイルに書かない（メモリのみ） |
| `--quiet` | 検出レポート／警告を表示しない |
| `--wipe`（`unmask`） | 復元後に mapping を破棄する |
| `--version` | バージョンを表示する（不具合報告に添えること） |

### 送信前のレビュー

`--html` は**自己完結した単一HTML**を出力する。検出された箇所がハイライトされ、
「どの層がなぜ検出したか」の根拠が付く。

```console
$ namemask mask memo.txt --no-ner --address --html review.html -o masked.txt
レビューHTML: review.html（原文を含む生の機密。外部に出さないこと。レビュー後は削除推奨）
```

外部CDN・外部JS・ネットワークアクセスを一切使わない。
ただし**このHTMLは原文（＝機密）を含む**ので、mapping と同等に扱うこと。
そのため **`0600` で作成する**（mapping と同じ。POSIX で実効・Windows は ACL 管理下）。
レビューが終わったら削除すること。`-o` のマスク済み出力は機密として扱わない。

### 取引先辞書

辞書層は、**すでに知っている取引先の recall を 100% にする**ための層である。
法人格の付かない通称・略称も、ここに書いておけば確実に落ちる。
`--clients` に CSV（`name,type,aliases`・`aliases` は `|` 区切り）を渡す:

```console
$ cat clients.csv
name,type,aliases
株式会社サンプル商事,ORGANIZATION,サンプル|Sample Trading

$ echo 'サンプルの新プロジェクトについて、Sample Trading 側と調整中。' \
    | namemask mask --no-ner --clients clients.csv --no-save
=== マスク結果: 2 件 ===
  [[組織_1]]      組織      サンプル   <- denylist
  [[組織_2]]      組織      Sample Trading   <- denylist
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
[[組織_1]]の新プロジェクトについて、[[組織_2]] 側と調整中。
```

表記バリアントは自動で展開される。全角／半角、空白とハイフンの揺れ、法人格を外した
コア名（`サンプル商事`）、法人格の前置・後置の両方（`株式会社サンプル商事` /
`サンプル商事株式会社`）が対象になる。**書くのは正式名称だけでよく、全表記を列挙する必要はない。**

> **既知の限界 — 濁点・半濁点つきの半角カナは対象外。**
> 座標対応を厳密に保つため正規化を**1文字ずつ**適用しており、原文で別々の
> コードポイントに分かれた合成列（`ﾌ` + `ﾟ`）は結合されない。そのため
> `ｻﾝﾌﾟﾙ` は辞書の `サンプル` と一致しない（濁点を含まない半角カナは一致する）。
> 修正までの回避策（[#4](https://github.com/sou-kurakata/namemask/issues/4)）は
> **半角カナ表記を alias に足すこと。** キー側も同じ fold を通るので一致する:
>
> ```console
> $ cat clients.csv
> name,type,aliases
> 株式会社サンプル商事,ORGANIZATION,サンプル|Sample Trading|ｻﾝﾌﾟﾙ
>
> $ echo 'ｻﾝﾌﾟﾙの件でご連絡しました。' \
>     | namemask mask --no-ner --clients clients.csv --no-save
> === マスク結果: 1 件 ===
>   [[組織_1]]      組織      ｻﾝﾌﾟﾙ   <- denylist
> ※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
> [[組織_1]]の件でご連絡しました。
> ```

```console
$ echo 'サンプル商事とサンプル商事株式会社、㈱サンプル商事の3表記。' \
    | namemask mask --no-ner --clients clients.csv --no-save
=== マスク結果: 3 件 ===
  [[組織_1]]      組織      サンプル商事   <- denylist
  [[組織_2]]      組織      サンプル商事株式会社   <- structural,denylist,boundary
  [[組織_3]]      組織      ㈱サンプル商事   <- structural,denylist
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
[[組織_1]]と[[組織_2]]、[[組織_3]]の3表記。
```

雛形は [`data/clients.sample.csv`](./data/clients.sample.csv)（架空データ）。
安全弁として、コア名が2文字以下の場合はコア名単体では照合しない（誤検出が多すぎるため）。
**実際の取引先マスタそのものが営業機密である。**バージョン管理に入れないこと
（`data/clients.csv` は `.gitignore` 済み）。

### ライブラリとして

```python
from namemask.api import mask_text, unmask_text

result = mask_text("株式会社サンプル商事の田中様", use_ner=False)
print(result.masked_text)   # [[組織_1]]の[[人名_1]]様
print(result.mapping)       # {'[[組織_1]]': '株式会社サンプル商事', '[[人名_1]]': '田中'}

restored = unmask_text(ai_reply, result.mapping)
print(restored.text)        # プレースホルダが実際の値に戻る
print(restored.unresolved)  # mapping に無いトークン（推測せず報告するだけ）
```

ライブラリAPIは mapping を**メモリ内のみ**に保持する。自分で書き出さない限り、
ディスクには何も残らない。CLI がフラグで見せている層は、`mask_text()` の
`clients_csv=` / `use_address=True` / `use_llm=True` で指定する。

## 精度

**99ケースの golden corpus**（すべて架空名）での実測値。決定的層＋住所層のみ、
NER・LLM off（`make eval` ＝ `python tests/eval.py --address`）:

| 指標 | 結果 |
|---|---|
| precision | **1.00** |
| 全体 recall（partial 基準） | **97.7%** |
| 辞書登録済み取引先（全バリアント表記込み） | **100%**（9/9） |
| 正規表現対象（EMAIL / PHONE / MYNUMBER・全角含む） | **100%**（79/79） |
| 法人格を含む組織名 | **100%**（22/22） |
| 住所・郵便番号（`--address` が必要） | **100%**（5/5） |
| round-trip 完全一致 | **100%** |

**`--address` を付けない場合、全体 recall は 95.9%** に下がり、住所型は 0 になる。
このフラグは精度の微調整ではなく、**PII の1カテゴリまるごとの on/off** である。

残る6件の検出漏れはすべて未知の固有名詞で、内訳は
**敬称の付かない署名ブロックの人名4件**と、**法人格を持たず辞書にも無い会社名2件**。
どちらも、optional な NER 層と自分の取引先辞書が埋めるべき穴である。

層を1つずつ外して測った recall 寄与（真のアブレーション）:
`structural` −36.4% ・ `regex` −29.4% ・ `denylist` −4.8% ・ `address` −1.9%。

この数値は **CI の閾値ゲート**になっている。下回る変更が入るとビルドが落ちる。
評価方法と見逃しの明細は [`docs/accuracy.md`](./docs/accuracy.md)。

## 仕組み

汎用PIIフレームワークのラッパーではない。**日本語のビジネス文書のために作った、
薄くて決定的なパイプライン**である。

1. **正規化層** — NFKC 正規化テキスト＋charmap。全角・半角の違いを吸収しつつ、
   座標は常に原文を指す。
2. **正規表現層** — メール、電話（5桁市外局番含む）、マイナンバー（チェックディジット検証）。
3. **構造ルール層** — recall の主力。法人格をアンカーに組織名、敬称をアンカーに人名を取る。
4. **辞書層** — 取引先リストを Aho-Corasick で照合。バリアント自動展開、
   fold 正規化テキスト上で照合する。
5. **住所層**（`--address`）— 郵便番号と、都道府県を起点とする住所。
6. **スパン統合層** — 境界拡張、重複解決、型優先度、組織コア名の文書内伝播。
7. **置換エンジン** — 原文座標に対して後方から前方へ適用。**同一表記は常に同一トークン。**

この上に、**追加専用・既定 off の optional 層**を2つ載せられる。どちらも既定インストールには含まれない:

- **NER**（`pip install namemask[ner]`）— GiNZA / spaCy。未知の固有名詞を補完する。
  導入すると CLI は自動で使い、`--no-ner` で飛ばせる。
- **LLM検証パス**（`--llm`）— ローカルの Ollama。マスクの**追加のみ**可能で、
  解除・変更は絶対にできない。エンドポイントはループバック限定で、明示的に指定しない限り off。
  Ollama は外部プロセスなので、追加の Python 依存は無い。

どちらも fail-safe。モデル未導入・ロード失敗でも決定的層によるマスクは残る
——層が抜けるだけで、パイプラインは止まらない。詳細は [`docs/design.md`](./docs/design.md)。

### 日本語のどこを手がかりにしているか

NER に頼らずに recall を出せているのは、日本語のビジネス文書に**強い表層の手がかり**が
あるからである。何が捕まり、何が意図的に捕まらないのかを、実際の挙動で示す。

**法人格アンカー（組織名）** — `株式会社` `有限会社` `合同会社` `合資会社` `合名会社`
`一般社団法人` `一般財団法人` `公益社団法人` `公益財団法人` `特定非営利活動法人` `NPO法人`
`独立行政法人` `国立大学法人` `社会福祉法人` `学校法人` `医療法人` `(株)` `(有)` を
前置・後置の両方で拾う。`㈱` `㈲` のような合字は正規化層が `(株)` `(有)` に畳むので、
同じ規則で一緒に落ちる。**法人格が付いている組織名は、辞書に無くてもほぼ確実に捕捉できる。**

**敬称アンカー（人名）** — `様` `さん` `氏` `殿` `先生` に加えて、役職の
`部長` `課長` `係長` `主任` `社長` `専務` `常務` `取締役` もアンカーになる。
スパンにするのは名前の部分だけで、敬称そのものは境界判定にしか使わない
（`田中様` → `[[人名_1]]様`）。日本語は分かち書きが無いため、そのままだと敬称の左隣の文字を
何文字取るかが問題になる。ここには2つのガードがある:

- **部署・役職の境界ガード** — `部課係室局店社庁省科班組隊` が候補に食い込んでいたら、
  その直後で切る（`営業部田中様` → `営業部` は残し `田中` だけをマスク）。
- **ストップワード** — `担当者` `関係者` `本人` `当社` `弊社` `貴社` `御社` `各位` などは
  敬称が付いても人名にしない。

```console
$ printf '株式会社サンプル商事 御中\n営業部田中様、ご担当者様、関係者各位\n' \
    | namemask mask --no-ner --no-save
=== マスク結果: 2 件 ===
  [[組織_1]]      組織      株式会社サンプル商事   <- structural
  [[人名_1]]      人名      田中   <- structural
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
[[組織_1]] 御中
営業部[[人名_1]]様、ご担当者様、関係者各位
```

`御中` も組織のアンカーで、法人格を持たない宛名（`サンプル商事 御中`）を拾うために使う。

**コア名の文書内伝播** — 初出で `株式会社サンプル商事` を捕まえたら、以降に法人格なしで
出てくる `サンプル商事` にも同じマスクを伝播させる。伝播先の前後が名称連続文字
（漢字・カタカナ）の場合は複合語の内部とみなして伝播しない。

```console
$ printf '株式会社サンプル商事と契約。サンプル商事の担当は佐藤さん。\n' \
    | namemask mask --no-ner --no-save
=== マスク結果: 3 件 ===
  [[組織_1]]      組織      株式会社サンプル商事   <- structural
  [[組織_2]]      組織      サンプル商事   <- structural,propagation
  [[人名_1]]      人名      佐藤   <- structural
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
[[組織_1]]と契約。[[組織_2]]の担当は[[人名_1]]さん。
```

**全角・半角の吸収** — 日本語文書のメールアドレスや電話番号は全角で書かれていることがある。
検出は NFKC 正規化テキスト上で行うので全角でも一致し、置換は原文座標に対して行うので、
**マスクされない部分の原文は1文字も変わらない。**

```console
$ printf '連絡先：ｔａｎａｋａ＠ｅｘａｍｐｌｅ．ｃｏ．ｊｐ／０３－１２３４－５６７８\n' \
    | namemask mask --no-ner --no-save
=== マスク結果: 2 件 ===
  [[メール_1]]     メール     ｔａｎａｋａ＠ｅｘａｍｐｌｅ．ｃｏ．ｊｐ   <- regex
  [[電話_1]]      電話      ０３－１２３４－５６７８   <- regex
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
連絡先：[[メール_1]]／[[電話_1]]
```

**住所（`--address`）** — 郵便番号は `〒` 付きのみを対象にする（裸の3桁-4桁を電話番号や
金額と取り違えないため）。住所は都道府県を起点に、番地の数字を含むか、
市区町村郡マーカーが**先頭以外**に現れるものだけを拾う。実在の住所では都道府県と最初の
「市／区／郡」の間に必ず市名・区名が入る（東京都**渋谷**区、大阪府**大阪**市）ことを
利用したガードで、`東京都市部` `市場調査` のような複合語を住所と誤判定しない。

```console
$ printf '東京都市部の市場調査について、北海道の気候も参考にする。\n' \
    | namemask mask --no-ner --address --no-save
=== マスク結果: 0 件 ===
※ 外部AIへ送る前に、上記の検出内容を必ずレビューしてください。
東京都市部の市場調査について、北海道の気候も参考にする。
```

**マイナンバー** — 12桁の数字のうち、**チェックディジットが妥当なものだけ**を検出する。
桁数だけで判定すると、注文番号や口座番号がすべてマイナンバーになってしまうため。

### 改変されたプレースホルダも復元する

外部AIは `[[組織_1]]` を `【組織_1】` `[人名 1]` `[[電話１]]`（全角数字）のように
書き換えて返してくることがある。復元は正確一致のあとに寛容照合を走らせ、
括弧種・空白・アンダースコア・全角数字の揺れを吸収する。
**寛容照合が働いたときは必ず警告を出す**ので、黙って直されることはない。
そして mapping に無いプレースホルダは、**推測で埋めずに未解決として報告する。**

```console
$ cat reply.txt
【組織_1】の[人名 1]様、[[電話１]]におかけしました。[[部署_9]]は不明です。

$ namemask unmask reply.txt -m mapping.json
警告: 改変されたプレースホルダを寛容照合で復元しました: [[組織_1]] (×1)
警告: 改変されたプレースホルダを寛容照合で復元しました: [[人名_1]] (×1)
警告: 改変されたプレースホルダを寛容照合で復元しました: [[電話_1]] (×1)
警告: mapping に対応の無い未解決プレースホルダが残っています（復元せず保持）: [[部署_9]]
株式会社サンプル商事の田中様、03-1234-5678におかけしました。[[部署_9]]は不明です。
```

未解決のプレースホルダが残った `unmask` は**終了コード 1** を返す（復元済みテキストは
そのまま出力される）。mapping が見つからない・復号できない場合は 2。
スクリプトから回す場合はここで検知できる。

## 設計上の保証（不変条件）

目標ではなく不変条件である。テストで担保している。

- **可逆。** `unmask(mask(x))` で原文が完全に復元される。
- **一貫。** 同じ表記は文書全体で常に同じトークンになる。
- **原文を書き換えない。** 正規化は原文とは別の正規化テキスト上、置換は常に原文座標に対して行う。
- **決定的。** 同じ入力→同じ出力。エージェントの推論ループでコアを駆動しない。
- **recall 最優先。** 見逃し＝漏洩、過剰マスク＝不便。迷ったらマスクする。
- **生値を捏造しない。** 復元できないトークンは未解決として報告し、推測で埋めない。
- **外部通信ゼロ。** telemetry も含む。LLM エンドポイントは、明示的に opt-out しない限り
  ループバック限定。

## 限界と免責

**namemask を業務で使う前に必ず読むこと。**

- **recall 100% は保証しない。** 実測は99ケースで 97.7%。未知の固有名詞
  ——特に珍しい姓、法人格の付かない通称の会社名、案件のコードネーム——は取りこぼす。
  取りこぼしたくないものは辞書に入れること。
- **マスク結果は必ず人間がレビューすること。** namemask はレビューの補助であって、
  自動ゲートではない。だからこそ、こちらから送信することは決してしない
  ——「マスクして送信」コマンドは意図的に存在しない。
  貼り付ける前に stderr のレポートか `--html` のページを読むこと。
- **「マスクした」は「外部に出してよい」を意味しない。** 仮名化しても外部AIに出せない
  データ種別はあり得る。その線引きは、このツールではなく利用者側の組織ポリシーの仕事である。
- **日本語専用。** 構造ルール層・辞書層は日本語の表記と商習慣に依存している。
- **mapping ファイルは生の機密。** 保存する場合は保護し、復元後に `--wipe` で破棄するか、
  `--encrypt` で AES 暗号化して保存する
  （`pip install namemask[crypto]`、パスフレーズは環境変数 `NAMEMASK_PASSPHRASE`）。

いかなる保証も提供しない。[LICENSE](./LICENSE) を参照。

## このリポジトリの範囲

このリポジトリは**検出エンジンと CLI のみ**である。これは意図的な線引きで、理由は
[ADR-0011](./docs/adr/0011-scope-oss-repo-to-core-and-cli.md) に書いてある。

対話的なレビューUI（誤検出の解除、テキスト選択による検出漏れの追加）と
Windows デスクトップ版は**別プロジェクト**にあり、このパッケージには含まれない。
いま対話的に直したいなら、`--html` でレビュー → 入力を修正 → 再実行、
あるいは `mask_text()` を自分のコードから呼ぶ形で対応できる。

`namemask serve` サブコマンドが欲しい場合は issue を立ててほしい。
**需要が確認できるかどうかが、v0.2.0 で UI を再統合するかの判断材料になる。**
