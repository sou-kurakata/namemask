# namemask（日本語版 README）

**社内の機密テキストを、外部AIに投げる前にローカルで仮名化し、応答を元の固有名詞に復元する。**

English: **[README.md](./README.md)**

---

## なぜ必要か

議事録・顧客メール・契約書ドラフトを ChatGPT / Claude / Gemini に投げたい。
でもそこには取引先の会社名・担当者名・電話番号・住所が入っている。

namemask はそれらを**完全ローカルで**仮名化し、外部AIに貼るためのマスク済みテキストを渡し、
AIの応答に含まれるプレースホルダを元の固有名詞に戻す。

```
原文 ──[namemask mask]──> マスク済み ──> 外部AI ──> 応答
                                                    │
原文の固有名詞に復元 <──[namemask unmask]───────────┘
```

**外部通信ゼロ。telemetry なし。namemask 自身が外部AIに送信することはない。**
送信は人間がコピー＆ペーストで行うので、何がマシンから出るかを必ず自分の目で確認できる。

## クイックスタート

```bash
pip install namemask
```

**辞書ファイルもモデルのダウンロードも不要。** 決定的層だけで即座に動く。

```console
$ cat memo.txt
株式会社サンプル商事の田中様より、新規案件のご連絡。
連絡先は tanaka@example.co.jp、電話 03-1234-5678。

$ namemask mask memo.txt -o masked.txt
$ cat masked.txt
[[組織_1]]の[[人名_1]]様より、新規案件のご連絡。
連絡先は [[メール_1]]、電話 [[電話_1]]。
```

`masked.txt` を**自分の目でレビューして**から外部AIへ貼る。応答を保存して:

```console
$ namemask unmask reply.txt -m .session/mapping.json -o restored.txt --wipe
```

`--wipe` は復元後に mapping ファイルを破棄する。
**mapping には原文の固有名詞がそのまま入っている。生の機密として扱うこと。**

### 主なオプション

| オプション | 効果 |
|---|---|
| `--clients data/clients.csv` | 取引先辞書を使う（登録済みの表記は recall 100%） |
| `--no-ner` | 決定的層のみ・高速（既定でも GiNZA 未導入なら自動でこうなる） |
| `--address` | 住所・郵便番号も検出 |
| `--llm` | ローカル Ollama の検証パスを追加（追加専用） |
| `--html report.html` | レビュー用の単一HTMLを出力（外部CDN・外部JS不使用） |
| `--encrypt` | mapping を AES 認証暗号で保存（`NAMEMASK_PASSPHRASE` が必要） |
| `--no-save` | mapping をファイルに書かない（メモリのみ） |

プレースホルダが `【組織_1】` `[組織 1]` のように外部AIに改変されて返ってきても、
寛容に復元する。

### 取引先辞書

`data/clients.sample.csv` が雛形。

```csv
name,type,aliases
株式会社サンプル商事,ORGANIZATION,サンプル|Sample Trading
有限会社テスト設計,ORGANIZATION,テスト設計事務所
```

`aliases` に略称・英語表記を `|` 区切りで書くと、バリアント展開されて全表記が捕捉される。
**このCSV自体が機密なので、リポジトリにコミットしないこと**（`.gitignore` 済み）。

### ライブラリとして

```python
from namemask import mask_text, unmask_text

result = mask_text("株式会社サンプル商事の田中様", use_ner=False)
print(result.masked_text)   # [[組織_1]]の[[人名_1]]様
print(result.mapping)       # {"[[組織_1]]": "株式会社サンプル商事", ...}

restored = unmask_text(ai_reply, result.mapping)
print(restored.text)
```

ライブラリAPIは mapping を**既定でメモリ内のみ**に保持する（ファイルに書かない）。

## 精度

**91ケースの golden corpus**（すべて架空名）での実測値。決定的層＋住所層のみ、NER・LLM off:

| 指標 | 結果 |
|---|---|
| precision | **1.00** |
| 全体 recall（partial 基準） | **97.7%** |
| 辞書登録済み取引先（全バリアント表記込み） | **100%** |
| 正規表現対象（EMAIL / PHONE / MYNUMBER・全角含む） | **100%** |
| 法人格を含む組織名 | **100%** |
| round-trip 完全一致 | **100%** |

この数値は **CI の閾値ゲート**になっている。下回る変更が入るとビルドが落ちる。
評価方法・層別アブレーション・残存する検出漏れの明細は
[`docs/accuracy.md`](./docs/accuracy.md)。

## 仕組み

汎用PIIフレームワークのラッパーではない。**日本語のビジネス文書のために作った、
薄くて決定的なパイプライン**である。

1. **正規化層** — NFKC の影テキスト＋charmap。全角・半角の違いを吸収しつつ、
   座標は常に原文を指す（逆変換可能）。
2. **正規表現層** — メール、電話（5桁市外局番含む）、マイナンバー（チェックディジット検証）。
3. **構造ルール層** — recall の主力。法人格（`株式会社` `有限会社` `㈱` …）を
   アンカーに組織名、敬称（`様` `さん` `部長` …）をアンカーに人名を取る。
4. **辞書層** — 取引先リストを Aho-Corasick で照合。バリアント自動展開、fold 済み影テキスト上で照合。
5. **住所層** — 郵便番号と都道府県起点の住所。
6. **スパン統合層** — 境界拡張、重複マージ、型優先度の解決、
   組織のコア名を文書内に伝播。
7. **置換エンジン** — 原文座標に対して後方から前方へ適用。
   **同一表記は常に同一トークン。**

この上に、**追加専用・既定 off の optional 層**を2つ載せられる:

- **NER**（`pip install namemask[ner]`）— GiNZA / spaCy。未知の固有名詞を補完。
- **LLM検証パス**（`pip install namemask[llm]`）— ローカルの Ollama。
  マスクの**追加のみ**可能で、解除・変更は絶対にできない。エンドポイントはループバック限定。

どちらも fail-safe。モデル未導入・ロード失敗でも決定的層の床は残る。
詳細は [`docs/design.md`](./docs/design.md)。

## 設計上の保証（不変条件）

目標ではなく不変条件。テストで担保している。

- **可逆。** `unmask(mask(x))` で原文が完全に復元される。
- **一貫。** 同じ表記は文書全体で常に同じトークンになる。
- **原文を書き換えない。** 正規化は影のコピー上、置換は常に原文座標に対して行う。
- **決定的。** 同じ入力→同じ出力。エージェントの推論ループでコアを駆動しない。
- **recall 最優先。** 見逃し＝漏洩、過剰マスク＝不便。迷ったらマスクする。
- **生値を捏造しない。** 復元できないトークンは未解決として報告し、推測で埋めない。
- **外部通信ゼロ。** telemetry も含む。LLM エンドポイントは明示的に opt-out しない限りループバック限定。

## 限界と免責

**namemask を業務で使う前に必ず読むこと。**

- **recall 100% は保証しない。** 実測 97.7%（91ケース）。未知の固有名詞
  ——特に珍しい姓、通称の会社名、案件のコードネーム——は取りこぼす。
- **マスク結果は必ず人間がレビューすること。** namemask はレビューの補助であって、
  自動ゲートではない。optional なローカルUIも「レビューせずに送信する」動線を意図的に持たない。
- **「マスクした」は「外部に出してよい」を意味しない。** 仮名化しても外部AIに出せない
  データ種別はあり得る。その線引きは利用者側の組織ポリシーで行う前提。
- **日本語専用。** 構造ルール層・辞書層は日本語の表記と商習慣に依存している。
- **mapping ファイルは生の機密。** 保存する場合は保護し、`--wipe` で破棄するか
  `--encrypt` で暗号化する。

いかなる保証も提供しない。[LICENSE](./LICENSE) を参照。

## 送信前のレビュー

`--html` は**自己完結した単一HTML**を出力する。検出された箇所がハイライトされ、
「どの層がなぜ検出したか」の根拠が付く。

```console
$ namemask mask memo.txt --html review.html -o masked.txt
```

外部CDN・外部JS・ネットワークアクセスを一切使わない。
ただし**このHTMLは原文（＝機密）を含む**ので、mapping と同等に扱うこと。

## このリポジトリの範囲

**検出エンジンと CLI のみ。** 意図的な線引きで、理由は
[ADR-0011](./docs/adr/) に書いてある。

対話的なレビューUI（誤検出の解除・テキスト選択による検出漏れの追加）と
Windows デスクトップ版は**別プロジェクト**にあり、このパッケージには含まれない。
対話的に直したい場合は、`--html` でレビュー → 入力を修正 → 再実行、
あるいは `mask_text()` を自分のコードから呼ぶ形で対応できる。

`namemask serve` が欲しい場合は issue を立ててください。
**需要が確認できれば v0.2.0 で UI の再統合を検討します。**
