# Design

このファイルは **現在の設計** だけを書く。判断の理由と却下した選択肢は
[`adr/`](./adr/) にある。本文中の `ADR-00NN` はそこへの参照。

---

## Scope

### やること

- 日本語の機密テキスト（取引先名・担当者名・連絡先・住所）を、外部AIに投げる**前**に
  ローカルで仮名化する。
- 外部AIの応答に含まれるプレースホルダを、**元の固有名詞へ復元**する。
- 「何をどのルールでマスクしたか」を人間がレビューできる形で出す
  （端末レポートと、依存ゼロの単一HTML）。
- 検出漏れ（recall）を数値で管理する。golden corpus と `tests/eval.py` が
  すべての変更の判断材料になる（[`accuracy.md`](./accuracy.md)）。

### やらないこと

- 外部AIへの自動送信。**人間のレビューを必須にする**ため、送信は自動化しない。
- クラウドPII検出API・ホスト型サービス。外部通信ゼロが要件
  （[`security.md`](./security.md)）。
- 画像・音声・PDF レイアウト。入力はプレーンテキストのみ。
- 完全な検出保証。自動検出には限界がある前提で、レビューで担保する。
- 日本語以外の言語のPII。

## Architecture

CLI 経路は一本道で、外部通信は無い。

```
┌─ ローカル（外部通信なし）────────────────────────────────────────┐
│                                                                  │
│  入力テキスト（原文・不変）                                        │
│      │                                                           │
│      ▼                                                           │
│  [0] 正規化: NFKC 影テキスト + charmap（原文座標への逆変換表）      │
│      │       辞書層用に fold 済み第2影テキストも作る                │
│      ▼                                                           │
│  ┌─ 検出層（それぞれ独立に走らせて union）──────────────────────┐  │
│  │ [1] 正規表現   EMAIL / PHONE / MYNUMBER                     │  │
│  │ [2] 構造ルール 法人格アンカー ORG / 敬称アンカー PERSON       │  │
│  │ [3] 辞書       取引先マスタ + バリアント展開（Aho-Corasick）  │  │
│  │ [4] 住所       〒 + 都道府県起点の住所（--address）           │  │
│  │ [5] NER        GiNZA（任意・fail-safe）                      │  │
│  └─────────────────────────────────────────────────────────────┘  │
│      │  スパン集合（重複あり・原文座標）                            │
│      ▼                                                           │
│  [6] スパン統合: 境界拡張 → 重複マージ・型解決 → 同一表記伝播 →    │
│      境界拡張 → 重複マージ                                        │
│      ▼                                                           │
│  [7] 置換: 型ごとの採番プレースホルダ [[組織_1]] + mapping         │
│      │    ＝ 決定的に保証されるマスク                              │
│      ▼                                                           │
│  [8] LLM 検証（任意）: 追加のみ。落ちても [7] の結果が残る          │
│      ▼                                                           │
│  masked_text (stdout) / report (stderr) / review.html / mapping   │
│      │                                                           │
│  【人間のレビュー】→ OK なら利用者が手でコピーして外部AIへ          │
│      │                                                           │
│  外部AIの応答（プレースホルダ入り）                                │
│      ▼                                                           │
│  [9] 復元: mapping で置換（長トークン優先 + プレースホルダ改変耐性） │
└──────────────────────────────────────────────────────────────────┘
```

モジュール境界:

- `api.py` — `mask_text` / `unmask_text`。ライブラリ利用者と CLI の共通入口。
- `pipeline/build.py` — 検出層の組み立て（層の有効/無効、アブレーション）。
- `pipeline/merger.py` — スパン統合。ここだけが「どのスパンを残すか」を決める。
- `core/replacer.py` `core/restorer.py` — 可逆性の心臓部。検出精度から独立。
- `cli.py` — 入出力・mapping の保存・レポート表示。検出ロジックを持たない。

## Stack

| Layer | Choice | ADR |
|---|---|---|
| 検出〜復元のパイプライン | 自前実装（Python・フレームワーク非依存） | 0001 |
| 正規化 | `unicodedata`（標準ライブラリ）＋ 自作 charmap | — |
| 辞書マッチ | `pyahocorasick`（部分文字列マッチ） | 0006 |
| 設定 | `PyYAML`（`config.yaml`） | 0009 |
| NER（任意） | GiNZA（`ja_ginza`）/ spaCy | 0003 |
| ローカルLLM（任意） | Ollama（ループバック限定・追加専用） | 0005 |
| mapping 暗号化（任意） | `cryptography`（Fernet + Scrypt） | — |
| テスト | pytest ＋ hypothesis（property-based） | 0002 |
| レビュー出力 | 依存ゼロの単一HTML（`review.py`） | 0011 |

必須依存は `pyahocorasick` と `PyYAML` だけ。NER・LLM・暗号化は extras。

## Detection layers

各層は**互いに独立**で、結果は union してから統合層に渡す。層を1つ落としても
残りは動く（`tests/eval.py` のアブレーションはこれを利用する）。

検出層には2種類ある:

- `ShadowDetector` — 影テキスト座標で検出する。`NormalizingDetector` が
  正規化とスパンの逆変換を引き受けるので、検出器本体は原文座標を知らない
  （`detectors/normalizing.py`）。正規表現・構造ルール・辞書・住所がこれ。
- `Detector` — 原文をそのまま受け取り原文座標を返す。NER がこれ
  （GiNZA が原文座標を返すため変換が不要）。

### 1. Normalization (`normalize.py`)

原文は**決して書き換えない。** 検出のための正規化は影のコピー上で行い、
スパンは必ず原文座標に戻してから統合層へ渡す。

**NFKC 影テキスト** — 原文を **1文字ずつ** `unicodedata.normalize("NFKC", ch)` し、
影テキストと `charmap`（影テキスト j 文字目 → 原文の文字インデックス）を同時に作る。
NFKC は 1→複数文字の展開がある（`㈱` → `(株)` で 1→3文字、全角英数 → 半角）ため、
展開を charmap で追跡する。これにより全角の電話番号・メールアドレス・`㈱` 表記が
素通りする典型事故を根絶しつつ、置換は常に原文座標に対して行える。

`NormalizedText.to_original_offsets()` は、**展開元の原文文字を必ず丸ごと含める**
（原文の1文字は分割できない）。

**fold 済み第2影テキスト** — 辞書照合専用の第2の影。NFKC 影に対してさらに
「空白除去」「ハイフン類の同一視」を行い、fold-charmap を保持する。NFKC は
ハイフン類（`ー` `−` `‐` `―` 等）と空白を吸収しないため、辞書キー `スカイテック` に
対する本文 `スカイ−テック` を NFKC 影だけでは拾えない。fold は文字を「消す」ため
charmap は 0 文字対応を含む（空白は影に現れない）。正規表現層・構造ルール層は
空白とハイフンが意味を持つので fold しない（ADR-0007）。

**ハイフン類の単一の真実** — `HYPHEN_CHARS` を公開定数として置き、数字区切りを
扱う検出器（住所・郵便番号）はこの集合から文字クラスを生成する。各検出器が
独自にハイフンを列挙すると定義がドリフトする。

**既知の限界** — NFKC を1文字ずつ適用するため、原文で別々のコードポイントに
分かれた合成列（半角カナ `ｶ` + 濁点 `ﾞ`）は結合されない（全文一括 NFKC なら `ガ` に
なる）。座標対応の厳密性を優先した仕様上のトレードオフ。主対象である
全角英数・全角記号・`㈱` は単一文字の展開なので影響を受けない。

### 2. Regex (`detectors/regex_ja.py`)

影テキスト上で動くので基本は半角前提で書ける。

- **EMAIL** — 前後がメール識別子文字でないことを要求して部分切り出しを防ぐ。
  境界判定は ASCII 限定にする（`\w` は日本語にもマッチし、`…は user@example.com` の
  ような日本語直後のメールを誤って弾く）。
- **PHONE** — 日本の `0` 始まりに限定。3分割ハイフン形は市外局番の桁数で分ける。
  2桁市外局番は `03` / `06` のみで、かつ `03-XXXX-XXXX` の 4-4 固定。任意の
  `0X-\d{1,4}-\d{3,4}` を許すと日付 `07-07-2026` を誤検出するため 4-4 に限定する。
  携帯・フリーダイヤル・IP電話・地方局番は 3〜5桁局番（5桁は実在する）。
  ハイフン無しの 10〜11桁も許容。ハイフン類は NFKC 非吸収の異体を含む文字クラスで受ける。
- **MYNUMBER** — 12桁で前後に数字が無いもののうち、**チェックディジット検証を
  通ったものだけ**を検出する（12桁の伝票番号を全部マイナンバーにしない）。
- **追加パターン** — `config.yaml` の `regex.extra_patterns`
  （`{name, type, pattern}`）から任意の正規表現を足せる。社内の案件コード等を
  コード変更なしにマスク対象にするための口。

### 3. Structural rules (`detectors/structural_ja.py`)

**recall の主力。** 日本語の強い表層手がかりを NER に任せず決定的に拾う（ADR-0003）。
法人格・敬称・名称の文字クラスは `lexicon.py` に一元化し、構造ルール層・辞書層・
統合層が同じ定義を使う。

**法人格アンカー（ORGANIZATION）** — `LEGAL_FORMS`（`株式会社` `(株)` `有限会社`
`一般社団法人` `特定非営利活動法人` `NPO法人` 等）の前置型 `株式会社◯◯` と
後置型 `◯◯株式会社` の両方。スパンは**法人格を含む全体**。法人格を含む一致は
誤検出がほぼ無いため信頼度 1.0 で扱う。名称部の長さは `org_name_max_len`（既定24）で
抑え、貪欲マッチを防ぐ。

**`御中` アンカー（ORGANIZATION）** — `御中` の直前を組織候補にする。`御中` は敬称
なのでスパンは名称部のみ。

**敬称アンカー（PERSON）** — `様 / さん / 氏 / 殿 / 先生` と役職語
（`部長 / 課長 / 係長 / 主任 / 社長 / 専務 / 常務 / 取締役`）の直前 1〜`person_max_len`
（既定4）文字を人名候補にする。スパンは**名前部分のみ**（敬称は境界判定にのみ使う）。
2つのガードを持つ:

- **左境界ガード** — 候補に部署・役職の境界文字（`部課係室局店社庁省科班組隊`）が
  食い込んでいたら、その直後で切る（`営業部田中様` → `業部田中` ではなく `田中`）。
- **ストップワード** — `皆 / みな / お客 / 客 / 奥 / 各位`（`config.yaml` で上書き可）に
  加え、常に除外する一般語（`担当者 / 担当 / 責任者 / 関係者 / 当社 / 弊社 / 貴社 /
  御社 / 本人` 等）。`ご担当者様` `お客様` を人名にしない。

**名称の文字クラス** — 組織・人名とも**ひらがなを含めない**。ひらがなを許すと
助詞が名称に混入する（＝「助詞・句読点で停止」の実装）。ひらがなを含む社名は
辞書層と NER に委ねる。

### 4. Dictionary (`detectors/denylist.py`)

既知の取引先を**どの表記でも**落とす層。**辞書に載っている取引先の recall は
100% が受け入れ基準**（[`accuracy.md`](./accuracy.md)）。

**CSV フォーマット**（`data/clients.sample.csv` が雛形。この節が仕様の正）:

| 列 | 必須 | 意味 |
|---|---|---|
| `name` | ○ | 正式名称。空行は無視 |
| `type` | | エンティティ型。既定・未知値は `ORGANIZATION` |
| `aliases` | | 略称・英名・旧社名。**縦棒 `\|` 区切り**で複数 |

`config.yaml` の `denylist.clients_csv` / `persons_csv` で場所を指定する。
`persons_csv` は同じ形式で、読み込んだ行の型を `PERSON` に上書きする。
**パスが存在しなくてもエラーにしない**（辞書層なしで起動する）。取引先マスタ自体が
機密であり、配布物に同梱できないため、辞書なしで動くことが前提になっている。

**バリアント展開**（`expand_variants`）— 1行から照合キー集合を作る:

1. 原表記（`株式会社アオヤマ商事`）
2. 法人格を剥がしたコア名（`アオヤマ商事`）— **本文では法人格抜きが最頻**で、
   最重要のバリアント
3. コア名に代表法人格（`株式会社 / 有限会社 / (株) / (有)`）を前置・後置した形
4. `aliases` 列の各値

生成した全キーに `fold_for_dict()` を適用してから Aho-Corasick に積む。**本文側の
fold 影と同じ関数を通す**ことで照合が対称になる（片側だけ fold すると取りこぼす）。
全角/半角の差は NFKC が、空白・ハイフンの差は fold が吸収するので、キー側で
組合せを列挙する必要はない。

**安全弁** — コア名が `denylist.min_core_len`（既定3）未満なら、コア名単体では
登録しない（法人格付きの形でのみ照合する）。2文字のコア名は一般語と衝突して
誤マッチが多発するため。

**照合** — 日本語は分かち書きが無いので部分文字列マッチが必須。単語境界を前提と
するライブラリは使えない（ADR-0006）。

### 5. Address (`detectors/address_ja.py`)

`--address` で有効になる層。**単独の地名は対象にしない**（`北海道の気候` を
マスクしない）。

- **郵便番号** — `〒` 付きのみ（`〒123-4567`）。裸の3-4桁は誤検出源なので拾わない。
  区切りはハイフン類の異体を許容する。
- **住所** — 都道府県名で始まり、住所本体（漢字・カタカナ・数字・ハイフン類。
  ひらがなを含めないので助詞で停止する）が続くもののうち、
  (a) 本体に数字（番地）を含む、または (b) 市区町村郡マーカーが**本体の先頭以外**に
  現れるもの。

(b) の「先頭以外」条件は誤検出ガードになっている。実在の住所では都道府県と最初の
`市` / `区` / `郡` の間に必ず市名・区名が入る（東京都**渋谷**区、大阪府**大阪**市）。
この条件が無いと `東京都市部` `大阪府市場調査` のような複合語を住所と誤判定する。

### 6. Span merger (`pipeline/merger.py`)

全層のスパン（原文座標・重複あり）を、置換エンジンが前提とする**非重複スパン**へ
畳む。**「どのスパンを残すか」を決めるのはここだけ。**

適用順序は **境界拡張 → 重複マージ → 同一表記伝播 → 境界拡張 → 重複マージ**。
伝播で新しく生じた ORG スパンにも境界拡張を効かせるため、伝播の後にもう一度回す。

1. **境界拡張** — ORGANIZATION スパンの直前・直後に法人格があれば取り込む
   （`東京アオヤマ工業` + 直後の `株式会社` → 1スパン）。元スパンは消さずに拡張版を
   追加し、重複マージで最広が採用される。PERSON 直後の敬称は取り込まない。
2. **重複マージ** — 重なるスパン（接触のみは重なりに含めない）をクラスタにまとめ、
   最広範囲へ統合する。`sources` はクラスタ内の全層名の和（重複除去・出現順）。
3. **型解決** — クラスタ内で `SOURCE_PRIORITY` の最大値を持つスパンの型を採る。
   同点ならより長いスパン。
4. **同一表記伝播** — 検出済みの表記が本文の他の位置に未検出で残っていれば、同じ型で
   追加する。NER や構造ルールは同じ社名でも文脈で拾ったり落としたりするため、これが
   recall と**文書内の一貫性**を同時に稼ぐ。

伝播の詳細:

- 照合は **NFKC 影テキスト上**で行う。原文で raw 比較すると NFKC が同一視する表記揺れ
  （`ＡＣＭＥ` ↔ `ACME`、`㈱` ↔ `(株)`）が素通りする。見つけた位置は charmap で
  原文座標へ戻す。
- **ORG コア名の伝播** — ORGANIZATION は法人格を剥がしたコア名も伝播候補にする。
  「株式会社◯◯ … （以降は）◯◯」という再言及を拾うため。コア名は3文字以上に限る
  （辞書層の `min_core_len` と同じ安全弁）。
- **複合語境界ガード** — 伝播先の前後が名称連続文字クラス（漢字・カタカナ・英数・
  `々〆〇`・異体字セレクタ）なら複合語の内部とみなして伝播しない。`青葉様` を拾った後に
  `青葉区役所` の中の `青葉` へ伝播して `[[人名_1]]区役所` を作る事故を防ぐ。
  漢字は基本ブロックだけでなく CJK 拡張A〜F・互換漢字・IVS まで含める（基本ブロック
  だけだと拡張漢字を含む名前の途中でガードが外れる）。
- 長い候補から順に伝播し、既にカバーされた範囲には重ねない。

### Entity types

型は `types.py` が単一の真実の源。

| Type | Label (ja) | Placeholder example |
|---|---|---|
| PERSON | 人名 | `[[人名_1]]` |
| ORGANIZATION | 組織 | `[[組織_1]]` |
| LOCATION | 地名 | `[[地名_1]]` |
| ADDRESS | 住所 | `[[住所_1]]` |
| EMAIL | メール | `[[メール_1]]` |
| PHONE | 電話 | `[[電話_1]]` |
| MYNUMBER | マイナンバー | `[[マイナンバー_1]]` |

LOCATION は型として存在するが、決定的層は emit しない（単独の地名をマスクしないため）。
NER はラベルを LOCATION にマッピングするが、既定の `enabled_types` に含まれないので
出力されない。

**型解決の優先度**（`SOURCE_PRIORITY`。値が大きいほど信頼できる）:

| Source | Priority | 理由 |
|---|---|---|
| `stub` | 100 | テスト用（golden の正解スパンを直接流す） |
| `denylist` | 40 | マスタに型が明記されている＝最も確実 |
| `structural` | 30 | 法人格・敬称という決定的な手がかり |
| `address` | 25 | 決定的パターン。regex と同格〜やや上 |
| `regex` | 20 | 形式が確定している |
| `ner` | 10 | 統計的推論 |
| `llm` | 5 | 追加専用の保険 |

`boundary` `propagation` は統合層が付ける由来ラベルで、優先度は持たない（0）。
レビュー時に「なぜこのスパンが出たか」を説明するために `sources` に残る。

## Replace and restore

### Replacement (`core/replacer.py`)

このモジュールは**検出精度から独立**している。入力スパンの正しさは呼び出し側の責任で、
重なりのあるスパンを渡すと `ValueError` で落とす（統合層の責務違反を隠蔽しない）。

- **プレースホルダ** — `[[<日本語ラベル>_<連番>]]`。型ごとに、本文の初出順で 1 から採番する。
  外部AIが構造を壊しにくく、かつ人間が読める形。
- **同一表記 → 同一トークン** — `(型, 表層文字列)` をキーにトークンを再利用する。
  文書内の一貫性がこれで担保される。
- **後方から前方へ置換** — 原文座標に対し start 降順で適用する。前方から置換すると
  以降の座標がずれる。
- **番号の衝突回避** — 原文自身に `[[組織_1]]` やその改変形（`【組織_1】` 等）が含まれる
  場合、その番号は飛ばす（欠番を許容）。復元時の (1) 二重置換 と (2) 原文由来の
  文字列の誤復元 を、この1つの対策で同時に塞ぐ。判定には復元側の寛容パターンを使う
  （正準形は寛容形に包含されるため、これ1つで足りる）。

出力は `MaskResult{masked_text, mapping, report}`。`report` の各項目は
`{original, token, type, sources}` で、端末レポートとレビューHTMLの両方が使う。

### Restoration (`core/restorer.py`)

外部AIの応答からプレースホルダを元の固有名詞に戻す。3パス構成:

1. **正確一致** — mapping のトークンを**長い順**に置換し、`[[組織_1]]` が
   `[[組織_11]]` の一部を壊す事故を防ぐ。
2. **寛容照合** — 外部AIはプレースホルダを改変して返すことがある
   （`[組織1]` `【組織_1】` `[[組織 _1]]` `[[組織１]]`）。括弧種・空白・アンダースコアの
   揺れと**全角数字**を許容するパターンで第2パスを回す。番号の大きい方から処理し、
   `1` が `11` に食い込むのを防ぐ。適用したら警告を出す（黙って直さない）。
3. **未解決の報告** — mapping に対応の無いプレースホルダらしき残骸は
   **復元せずそのまま残し**、`unresolved` として報告する。**生値を捏造しない。**
   CLI は未解決があれば終了コード 1 を返し、呼び出し側が検知できるようにする。

### Mapping lifecycle

`mapping`（token → 原文）は**生の機密**。扱いは経路によって違う:

- **ライブラリ API** — `mask_text()` の戻り値に含まれるだけで、**ファイルに書かない。**
  保存するかどうかは利用者が決める。
- **CLI** — `mask` と `unmask` が別プロセスなので保存が要る。既定の保存先は
  `paths.mapping_path()`（= `app_data_dir()/.session/mapping.json`）。
  `--no-save` でメモリのみ、`--mapping` で場所を変えられる。保存時は
  **stderr に警告を出し**、`unmask --wipe` / `wipe` サブコマンドで破棄できる。

保存時のパーミッション: ディレクトリ `0o700` / ファイル `0o600`。既存ファイルの緩い
パーミッションを引き継がないよう、いったん削除してから `O_CREAT` に `0o600` を渡して
作り直す（umask の影響を受けにくい）。Windows では POSIX パーミッションが実効しない
（ACL 制御は別途必要）。

**暗号化**（任意）— `--encrypt` と環境変数 `NAMEMASK_PASSPHRASE` で、Fernet
（AES128-CBC + HMAC-SHA256）で保存する。鍵は Scrypt でパスフレーズから導出し、ソルトは
暗号文に同梱する。認証付きなので改竄・パスフレーズ不一致は復号失敗として検知され、
生値を推測復元しない。`cryptography` は任意依存で、未導入なら明確なエラーを出す
（**平文フォールバックはしない** — 機密の意図せぬ平文保存を防ぐ）。

## Optional layers (additive, off by default)

どちらも **fail-safe**: 利用不可でも決定的層の検出結果は変わらない。**マスクの追加のみ**行える。

### NER (`detectors/ner.py`)

決定的層で拾えない「手がかりの無い固有名詞」（署名内の敬称なし人名など）を補う。
GiNZA（既定 `ja_ginza`）は原文をそのまま解析して原文座標を返すため、影テキスト変換を
通さない。

- **ラベルマッピングを明示的に持つ**（`ner_labels.py`）。GiNZA は関根の拡張固有表現
  （ENE）体系のラベルを出す（`Person` / `Company` / `Corporation_Other` / `City` …）。
  対応表で PERSON / ORGANIZATION / LOCATION に変換し、**表に無いラベルは黙って捨てず
  warning を出す**（ラベル名のみ。本文は絶対に出さない）。ここのマッピング漏れが
  「NER は動いているのにマスクされない」典型バグ。
- 既定で emit するのは PERSON と ORGANIZATION のみ。
- スコアは固定値（`ner.score_threshold`、既定 0.5）。GiNZA は確信度を出さないため、
  統合層の優先度計算に載せるための値として扱う。
- 前後の空白・改行はスパンから除く。
- **fail-safe** — spaCy 未導入・モデル読み込み失敗・推論失敗のいずれでも `[]` を返し、
  例外名だけを warning に出す。CLI は既定で NER を有効にするが（`--no-ner` で無効化）、
  GiNZA が無い環境では自動的に決定的層のみで動く。

### LLM verifier (`detectors/llm_verifier.py`)

決定的（＋NER）統合の**後段**に走る独立パス。精度の主役ではなく、「辞書にもルールにも
載らない未知固有名詞」の保険（ADR-0005）。`--llm` で有効。

- **入力** — 本文を文境界（`。！？` 改行）で `llm.chunk_chars`（既定700）程度に分割し、
  チャンクごとに問い合わせる。既にマスク済みの表層文字列を同時に渡す。
- **プロンプト** — 「まだマスクされていない固有名詞だけを JSON で返す。既存マスクの
  解除・変更はしない」＋ few-shot 3例（追加あり / 追加なし空配列 / 既存に触れない）。
  Ollama の `/api/generate` に `format: json` `temperature: 0` で投げる。
- **追加専用の構造的な保証** — 返ってくるのは追加候補の配列だけで、コードは既存スパンに
  一切触れない。LLM が何を返しても最悪ケースは「過剰マスク」に固定される。
- **幻覚防御** — 返された表層文字列が**チャンク内に実在する位置**にだけスパンを作る。
  原文に無い文字列は破棄。長さが2〜40文字の範囲外のものも捨てる。
- **ループバック強制** — エンドポイントのホストが `localhost` / `127.0.0.0/8` / `::1` で
  なければ**例外で拒否する。** ホスト名の DNS 解決はしない（解決自体が外部通信になり得る
  うえ、外部へ解決されるホスト名を許すと穴になる）。唯一の安全弁が
  `llm.allow_remote: true` で、既定は false（[`security.md`](./security.md)）。
- **fail-safe** — Ollama 不在・タイムアウト・JSON 破損は、そのチャンクの追加を
  スキップして決定的結果をそのまま採用する。

## Paths and data directory

`paths.py` が書き込み先の**単一の真実の源**。cwd と `__file__` への依存をここに閉じ込める。

| 関数 | 通常実行 | 凍結ビルド（`sys.frozen`） |
|---|---|---|
| `app_data_dir()` | `.`（カレントディレクトリ） | `%LOCALAPPDATA%\namemask`（無ければホーム配下） |
| `config_path()` | リポジトリ同梱の `config.yaml`（`__file__` 起点） | `app_data_dir()/config.yaml` |
| `session_dir()` | `./.session` | `%LOCALAPPDATA%\namemask\.session` |
| `mapping_path()` | `./.session/mapping.json` | 同上 `/mapping.json` |
| `log_dir()` | `./logs` | `%LOCALAPPDATA%\namemask\logs` |

- **既定パスは import 時の定数ではなく、呼び出し時に解決する。** 凍結判定と環境変数を
  実行時に反映するため（ADR-0008）。`config.py` `core/mapping.py` `cli.py` はこの方針に従う。
- `app_data_dir()` は**副作用の無い純関数**。ディレクトリは作らない。作成は書き込み時
  （`MappingStore.save()` / `ensure_config_file()`）に限る。
- 凍結分岐を残しているのは、同じ `paths.py` を配布物（別プロジェクト）でも使うため。
  通常実行の挙動には影響しない（`is_frozen()` は常に `False`）。
  **この分岐に新しい機能は足さない**——PyInstaller 固有の要求は別プロジェクト側の担当
  （ADR-0008 の Follow-up）。

**テキスト入出力の符号化と改行**（`cli.py`）— 読み書きはすべて `encoding="utf-8"` を
明示し、**改行コードを一切変換しない**（`newline=""`）。text モードの既定は環境依存で、
読みで CRLF を LF に畳み、書きで LF を `os.linesep` に展開する。これを放置すると
CRLF 文書を mac / Linux で処理すると LF になり、LF 文書を Windows で処理すると CRLF に
なる ——「原文を書き換えない」「`unmask(mask(x))` は原文に一致する」が壊れる。
入力ファイル・出力ファイル・レビューHTML・標準入出力（`reconfigure(newline="")`）の
4経路すべてで変換を止める。回帰ガードは `tests/test_cli.py` の
`test_crlf_line_endings_survive_roundtrip` / `test_lf_line_endings_are_not_converted` /
`test_stdin_stdout_pipe_preserves_crlf`（バイト列で比較する。`read_text()` は
変換してしまい退行を検出できない）。

**設定の読み込み**（`config.py`）— `config.yaml` が無い、または一部が欠けていても
安全な既定値で動く。既定値は `Config` の各アクセサが持ち、雛形テキストと一致させる。
雛形の書き出し（`ensure_config_file()`）は `load_config()` の副作用にせず、明示的に
呼ぶ関数として分ける（ADR-0009）。読むだけのつもりの呼び出しがファイルを作る挙動は、
読み取り専用環境や並行実行で事故になる。

## Review output (`--html`)

`review.py` が原文と `MaskResult` から**単一の自己完結HTML**を生成する。

- **外部依存ゼロ。** CDN・外部JS・外部フォント・外部画像を一切参照しない。
  CSS は `<style>` にインラインで埋め込む。原文（＝機密）を含むファイルが、開くだけで
  外部へリクエストを飛ばすことがあってはならない。JavaScript も使わない。
- **表示内容** — (1) マスク済みテキスト（送信対象）、(2) 検出根拠の表
  （トークン / 型 / 原文 / どの層が検出したか）、(3) 原文（`<details>` で折りたたみ）。
- **ハイライト** — マスク済みテキスト中のトークンを `<mark>` で囲み、`title` 属性に
  「元の値 / 型 / 検出根拠」を出す。トークンは長い順に照合して部分一致事故を防ぐ。
- **エスケープ** — 原文由来の文字列はすべて `html.escape()` を通す。トークンは ASCII
  なのでエスケープしても不変。
- **警告を目立たせる** — 「送信前に必ず確認すること」と「**このファイルは原文を含むので
  外部に出さないこと**」をページ冒頭に出す。この出力は mapping と同等の機密である。
