# ADR-0006: flashtext ではなく pyahocorasick を使う

- **Status**: Accepted
- **Date**: 2026-07-30 <!-- 旧 Planv2.md §13 からの移設日。原決定はプロトタイプ期（日付未記録） -->
- **Legacy ID**: ADR-006

## Context

辞書層（`detectors/denylist.py`）は取引先マスタ（数百〜数千件、バリアント展開後は
さらに増える）を本文から一括で探す。素朴に「キーごとに `str.find`」を回すと
キー数 × 本文長になるため、多パターン文字列マッチのライブラリを使いたい。

Python でこの用途によく挙がるのは flashtext と pyahocorasick の2つ。

決定的な制約は**日本語には分かち書きがない**こと。`株式会社あおぞら商事` の中の
`あおぞら商事` は、前後に空白も区切り記号もない状態で現れる。

## Options considered

### (A) flashtext

- 利点: 純 Python でビルド不要。API が単純。置換機能も持っている。
- 欠点: **単語境界を前提としたマッチング**を行う。空白や区切り文字で
  区切られたトークンとしてキーが現れることを想定しているため、
  日本語の部分文字列マッチには使えない。

### (B) pyahocorasick

- 利点: Aho-Corasick 法による純粋な部分文字列マッチ。単語境界の概念がなく、
  日本語でそのまま使える。C 実装で高速。オートマトンを一度作れば
  本文長に対して線形で全キーを走査できる。
- 欠点: C 拡張なのでビルド済み wheel が無い環境ではコンパイルが要る。

## Decision

**(B) pyahocorasick を採用する。**

(A) を却下した理由は単純で、**日本語では動かない**から。flashtext の
単語境界前提は英語圏のテキストには合理的だが、分かち書きのない日本語では
`あおぞら商事` が独立したトークンとして現れることはまずない。
利便性の差ではなく、要件を満たすかどうかの差である。

C 拡張であることのコストは受け入れる。主要プラットフォーム（Linux / macOS /
Windows）には wheel が提供されており、`pip install namemask` の体験は損なわれない。

## Consequences

- `pyahocorasick` が数少ないランタイム依存の1つになっている
  （もう1つは `PyYAML`）。ADR-0001 の「依存を最小化する」方針の中で、
  ここは意図的に払っているコスト。
- 部分文字列マッチであることは諸刃で、短いコア名（`青` など）が
  無関係な語に当たりうる。この安全弁が `config.yaml` の
  `denylist.min_core_len`（既定 3。コア名が2文字以下なら法人格付きでのみ照合）。
- CI は Linux / macOS / Windows で `pip install` からのスモークを回す
  （`CLAUDE.md` §5）。C 拡張のビルド・wheel 取得の退行はここで捕まえる。
- **見直し条件**: pyahocorasick が主要プラットフォームで wheel を出さなくなり、
  インストールの障壁になった場合。代替は純 Python の Aho-Corasick 実装であって、
  flashtext ではない（要件を満たさないため）。
