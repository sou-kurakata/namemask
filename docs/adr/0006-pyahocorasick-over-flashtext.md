# ADR-0006: flashtext ではなく pyahocorasick を使う

- **Status**: Accepted
- **Date**: 2026-07-30 <!-- ADR として起こした日。原決定はプロトタイプ期（日付未記録） -->
- **Legacy ID**: ADR-006

## Context

辞書層（`detectors/denylist.py`）は取引先マスタ（数百〜数千件、バリアント展開後は
さらに増える）を本文から一括で探す。素朴に「キーごとに `str.find`」を回すと
キー数 × 本文長になるため、多パターン文字列マッチのライブラリを使いたい。

Python でこの用途によく挙がるのは flashtext と pyahocorasick の2つ。
両者の差は、キーを語として探すか、部分文字列として探すかにある。

日本語には分かち書きがないので、この差がそのまま効く。`株式会社あおぞら商事` の中の
`あおぞら商事` は、前後に空白も区切り記号もない状態で現れる。語を単位とする実装を
この本文に当てるには、先に何らかの手段で語の境界を与える必要がある。

辞書層が満たすべき制約は2つ。

- 辞書登録済み取引先の recall は受け入れ基準で 100%（`CLAUDE.md` §6）。
  表記揺れで1件落ちることも許されない。
- 辞書層は決定的層である（ADR-0003）。統計モデルに結果を左右されない。

## Options considered

### (A) flashtext に形態素解析器を組み合わせ、先に語へ分割してから照合する

- 利点: 純 Python でビルド不要。API が単純。置換機能も持っている。
  分割器は新規調達ではなく、GiNZA を `ner` extra として既に持っている。
- 欠点: 辞書層が分割器に依存する。GiNZA は既定 off の optional extra なので、
  辞書層のためにこれを必須依存へ格上げすることになる。
  さらに、分割の結果は解析器と同梱辞書のバージョンで変わる。`あおぞら商事` が
  1語として切り出される保証はどのバージョンにも無く、キーと境界がずれた時点で
  recall が落ちる。落ちても例外は出ない。

### (B) pyahocorasick で部分文字列として照合する

- 利点: Aho-Corasick 法による純粋な部分文字列マッチ。語の境界という概念がないので
  分割そのものが要らない。C 実装で、オートマトンを一度作れば本文長に対して
  線形で全キーを走査できる。
- 欠点: C 拡張なのでビルド済み wheel が無い環境ではコンパイルが要る。

## Decision

**(B) を採用する。**

(A) を却下したのは「日本語では動かないから」ではない。形態素解析で先に分割すれば
flashtext でも辞書層は成立する。却下したのは、そのために払う対価が、
このプロジェクトが先に守ると決めた2つの方針と衝突するため。

1. 依存を増やさない（ADR-0001）。ランタイム依存は `PyYAML` と `pyahocorasick` の
   2本で、GiNZA は optional extra・既定 off に置いている。辞書層は
   `pip install namemask` だけで動く必要がある。分割器を必須にすると、
   ADR-0003 で NER を追加層に留めて避けたモデルの同梱・配布の問題が、
   今度は決定的層の側から入ってくる。
2. 決定的層の結果をモデルのバージョンに依存させない（ADR-0003・不変条件4）。
   辞書 recall の 100% は受け入れ基準であって努力目標ではない。これを分割器の
   バージョンに紐づけると、解析器を更新した日に気づかないまま割れる。

優先順位は 2 が先に効く。仮に必須依存が1本増えることを受け入れたとしても、
recall 100% の保証をモデルのバージョンに預ける選択は取れない。辞書層は
「登録したものは必ず落とす」という約束の実装であり、そこが確率的になるなら
辞書層である意味がなくなる。

pyahocorasick はこの対価をどちらも払わずに済む。部分文字列マッチなので分割が要らず、
依存は C 拡張1本で閉じる。C 拡張であることのコストは受け入れる。主要プラットフォーム
（Linux / macOS / Windows）には wheel が提供されており、`pip install namemask` の
体験は損なわれない。

flashtext を分割器なしで日本語本文に当てたときの挙動は未計測。上の判断は分割器を
挟む前提で行っているので、素の挙動がどうであっても結論は変わらない。

## Consequences

- `pyahocorasick` が数少ないランタイム依存の1つになっている
  （もう1つは `PyYAML`）。ADR-0001 の「依存を最小化する」方針の中で、
  ここは意図的に払っているコスト。
- 辞書層は形態素解析器を持たない。登録済み取引先の recall 100% を外部モデルの
  バージョンから切り離すための選択なので、辞書層に分割器を入れる変更は
  ADR-0003 の帰結ごと再検討することになる。
- 部分文字列マッチであることの代償として、短いコア名（`青` など）が
  無関係な語に当たりうる。この安全弁が `config.yaml` の
  `denylist.min_core_len`（既定 3。コア名が2文字以下なら法人格付きでのみ照合）。
- CI は Linux / macOS / Windows で `pip install` からのスモークを回す
  （`CLAUDE.md` §5）。C 拡張のビルド・wheel 取得の退行はここで捕まえる。
- **見直し条件**: pyahocorasick が主要プラットフォームで wheel を出さなくなり、
  インストールの障壁になった場合。代替はまず純 Python の Aho-Corasick 実装を探す。
  flashtext は、分割器を必須依存にすることと recall をそのバージョンに預けることが
  変わらないため、この場合も候補にならない。
