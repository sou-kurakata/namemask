# ADR-0009: config 雛形の書き出しは `load_config()` の副作用にせず明示関数にする

- **Status**: Accepted
- **Date**: 2026-07-30 <!-- ADR として起こした日。原決定はプロトタイプ期（日付未記録） -->
- **Legacy ID**: ADR-107

## Context

`config.yaml` は非エンジニア（情シスの指定値を書き写す人）が編集する前提の
ファイルなので、初回起動時に日本語コメント入りの雛形を自動で書き出したい。

素直な置き場所は `load_config()` の中である —— 「読もうとして無ければ作る」。
しかし `load_config()` は次のような関数になっている:

- 検出パイプラインの各所から呼ばれる。
- テストからも多数回呼ばれる（`tmp_path` や不定な cwd の下で）。
- 引数だけで結果が決まるべき、実質的に純関数。

ここにファイル書き込みを埋め込むと、**設定を読んだだけで副作用が起きる。**
テストの temp dir や、起動時の不定な cwd に予期しない `config.yaml` が生まれる。
これは「cwd に勝手に書かない」という方針（ADR-0008 と同じ懸念）と正面衝突する。

## Options considered

### (A) `load_config()` が、ファイルが無ければ雛形を書き出してから読む

- 利点: 呼び出し側が何も意識しなくてよい。初回起動で必ず雛形ができる。
- 欠点: 純関数であるべき関数が副作用を持つ。テスト実行のたびに、
  検出パイプラインを叩くたびに、どこかへ `config.yaml` が生まれる。
  どの呼び出しが書いたのか追えない。

### (B) 読み込みと雛形書き出しを分け、書き出しは明示関数
`ensure_config_file()` にする

- 利点: `load_config()` が副作用のない読み取りに戻る。雛形を作る責務が
  アプリの起動シーケンスの1行として見える。テストが汚れない。
- 欠点: 起動シーケンス側が `ensure_config_file()` を呼ぶことを覚えている必要がある。
  呼び忘れると雛形ができない。

## Decision

**(B) を採用する。**

(A) を却下したのは、副作用の発生箇所が呼び出しグラフ全体に散ってしまうため。
`load_config()` はパイプライン全域から呼ばれるので、「どこかで config.yaml が
作られる」を「どこで作られたか」に絞り込めなくなる。

雛形書き出しは `ensure_config_file()` に分離し、**アプリの起動シーケンスから
明示的に一度だけ**呼ぶ。ファイルが既にあれば上書きしない。

`load_config()` はファイルが無くても安全な既定値（`Config(raw={})`）で動く。
つまり雛形が無い状態でもツールは起動する（fail-safe）—— 呼び忘れの罰は
「雛形ファイルが用意されない」だけで、動作不能にはならない。

## Consequences

- `config.py` に3つの関数が並ぶ: `load_config()`（副作用なしの読み取り）/
  `default_config_template()`（雛形の文字列）/ `ensure_config_file()`（書き出し）。
- 雛形の値は `Config` の各アクセサの既定値と一致させる必要がある。
  ここが食い違うと「雛形どおりに書いたのに挙動が違う」になる
  （`config.py` の `_CONFIG_TEMPLATE` にその旨のコメントがある）。
- 書き出し先は `paths.config_path()` を呼び出し時に解決する（ADR-0008）。
  ディレクトリ作成もこの関数の中で行う —— 副作用は書き込み側に集める、
  という ADR-0008 の分担と一致している。
- `tests/test_paths.py` が両モード（開発 / 凍結）での解決先と、
  既存ファイルを上書きしないことを検証している。
- **このリポジトリには `ensure_config_file()` の本番呼び出し元がない。**
  呼んでいたのはデスクトップアプリの起動シーケンスで、それは別リポジトリ
  `namemask-app` 側にある（ADR-0011）。`namemask` CLI は config が無くても
  既定値で動くため、雛形を必要としていない。関数は公開 API として残す
  （アプリ側が呼ぶ／利用者が自分で雛形を得られる）。
- **見直し条件**: CLI 自身が雛形を必要とするようになった場合。
  その時は「どのサブコマンドで一度だけ呼ぶか」を決めてここに追記する
  （`load_config()` に戻さない、というのがこの ADR の要点）。
