# ADR-0007: 辞書照合は fold 済み第2影テキスト上で行う

- **Status**: Accepted
- **Date**: 2026-07-30 <!-- ADR として起こした日。原決定はプロトタイプ期（日付未記録） -->
- **Legacy ID**: ADR-007

## Context

辞書層は取引先マスタのコア名を本文から探す。ところが同じ社名が文書ごとに
違う書き方で現れる:

```
スカイテック    スカイ・テック    スカイ－テック    スカイ テック
株式会社スカイテック    ｽｶｲﾃｯｸ株式会社
```

全角・半角の揺れは NFKC 正規化（`normalize.py` の第1影テキスト）が吸収する。
残るのが空白の有無とハイフン類の種類。Unicode にはハイフンに見える文字が
10種以上あり（`-` `‐` `‑` `–` `—` `−` `－` `ー` …）、どれが使われるか予測できない。

辞書登録済み取引先の recall は受け入れ基準で 100%（`CLAUDE.md` §6）。
表記揺れで1件落ちることも許されない。

## Options considered

### (A) 辞書キー側でバリアントを展開し、ハイフン・空白の組合せを列挙する

- 利点: 本文側の処理が増えない。既存の Aho-Corasick オートマトンにキーを足すだけ。
- 欠点: 組合せ爆発する。`スカイ－テック` のようにハイフンが入りうる位置が
  2箇所あるだけで、10種以上のハイフン × 空白の有無で百を超えるバリアントになる。
  取引先が数千件あればオートマトンが現実的な大きさを超える。

### (B) 本文側に fold（空白除去＋ハイフン同一視）を適用した第2影テキストを charmap 付きで作り、辞書層だけをその上で照合する

- 利点: 本文を1回 fold するだけなので O(n) で完結する。バリアント展開は不要。
  NFKC 影テキストと同じ「影＋charmap」の既存機構をそのまま再利用できる。
- 欠点: 影テキストが2本になる。空白を「消す」ため charmap が
  0 文字対応を含むようになり、座標変換がやや複雑になる。

## Decision

**(B) を採用する。**

(A) を却下した決め手は組合せ爆発。ハイフンの種類 × 出現位置 × 空白の有無は
掛け算で効くため、コア名が長いほど悪化する。本文側を1回 fold する (B) は
本文長に対して線形で、しかも表記揺れの種類がいくつあっても変わらない。

fold 影は辞書層専用とする。正規表現層と構造ルール層では空白とハイフンが
意味を持つため（電話番号の区切り、法人格と社名の境界）、fold してはならない。

キー側にも本文側と同じ fold 関数を適用する。片方だけ fold すると
非対称になり取りこぼす。`normalize.fold_for_dict()` がその共通の入口。

不変条件6（原文は書き換えない）は影テキスト方式で保たれる。fold はあくまで
影の上の操作で、検出したスパンは charmap で原文座標へ戻してから置換される。

## Consequences

- 影テキストが2本ある: NFKC 影（`normalize()`）と fold 影（`fold_normalize()`）。
  どの層がどちらを使うかは `docs/design.md` §Detection layers の表が正。
- fold の charmap は 0 文字対応を含む（空白は fold 影に現れない）。
  `normalize.py` の charmap 構築はもともと文字の消失を追跡できる設計だったため、
  同じ方式で実装できている。
- 本文側とキー側の fold は必ず `normalize.fold_for_dict()` を通す。
  ここが非対称になると、気づかないうちに辞書 recall 100% が崩れる
  （`tests/test_normalize.py` / `tests/test_denylist.py`）。
- 副作用として、fold 影の上では「スカイ テック」のような空白入りの表記も
  1つのスパンとして拾えるが、復元される原文座標には空白が含まれる。
  置換は原文座標に対して行われるため round-trip は保たれる。
- **見直し条件**: 空白・ハイフン以外の表記揺れ（例: 長音の有無、旧字体）が
  問題になった場合。fold の規則を足すか、別の影を足すかをその時点で判断する。
