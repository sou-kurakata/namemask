# ADR-0003: NER より先に決定的層（正規化・構造ルール・辞書）で recall の床を作る

- **Status**: Accepted
- **Date**: 2026-07-30 <!-- ADR として起こした日。原決定はプロトタイプ期（日付未記録） -->
- **Legacy ID**: ADR-003

## Context

日本語の固有表現抽出には GiNZA / spaCy という既製の選択肢があり、
「PII 検出 = NER を回す」という発想は自然に出てくる。

一方でこのツールの制約は次のとおり:

- **recall 最優先**（不変条件2）。見逃し＝情報漏洩。
- **決定的コア**（不変条件4）。同じ入力 → 同じ出力。
- **完全ローカル**（不変条件3）。モデルもローカルに置く。
- 主な対象は日本語のビジネス文書（メール・議事録・見積書の類）。

そしてこの領域の文書には、統計モデルを介さずに拾える手がかりが濃く含まれている ——
法人格（株式会社・有限会社・合同会社…）、敬称（様・さん・部長…）、
そして利用者がすでに持っている取引先マスタ。

## Options considered

### (A) NER を主軸に据え、正規表現と辞書で補う

- 利点: 手がかりのない固有名詞も拾える。ルールを書く量が減る。
- 欠点: recall がモデルの気分に依存する。同じ文書でもモデルを更新すると結果が変わる
  （不変条件4に反する）。モデルの同梱・配布が必要になる。
  失敗したときに「なぜ拾えなかったか」を説明できない。

### (B) 決定的層（正規化・正規表現・構造ルール・辞書・住所）で recall の床を作り、
NER は「手がかりのない未知固有名詞」専任の追加層にする

- 利点: 床が決定的に保証される。モデルが無くても、壊れても、床は動かない。
  検出根拠が説明できる（どの層が拾ったか）。
- 欠点: 法人格も敬称も辞書登録も無い固有名詞は、NER を有効にしない限り落ちる。

## Decision

**(B) を採用する。**

(A) を却下した決め手は不変条件4との衝突。recall の主力が統計モデルだと、
「今日は拾えたものが明日は拾えない」ことが原理的にありうる。見逃し＝漏洩である以上、
**保証できる床**を持つことが、床の高さそのものより重要になる。

日本語ビジネス文書の機密エンティティの大半は法人格・敬称・取引先マスタという
決定的な手がかりで拾える、というのがこの決定の前提であり、実測がそれを裏づけている
（決定的層＋住所層のみで recall 97.7% / precision 1.00）。
NER は、その前提が当てはまらない残りの部分 —— 手がかりのない未知固有名詞 —— に
限定した追加専用の層として置く。既定 off。

決定性・監査性を優先し、統計的/生成的なものを追加専用に閉じ込めるという思想は
ADR-0005（LLM をオーケストレーターにしない）と同根である。

## Consequences

- 検出パイプラインの主力は `detectors/regex_ja.py`（EMAIL / PHONE / MYNUMBER）、
  `detectors/structural_ja.py`（法人格・敬称アンカー）、
  `detectors/denylist.py`（取引先マスタ）、`detectors/address_ja.py`（住所）。
- `detectors/ner.py` は optional extra（`pip install namemask[ner]`）で既定 off。
  GiNZA が入っていなくても、ロードに失敗しても、決定的層の結果は変わらない
  （fail-safe。`tests/test_ner_failsafe.py`）。
- 各層の寄与は `make eval` のアブレーションで測れる:
  structural -0.3643 / regex -0.2937 / denylist -0.0483 / address -0.0186。
  **構造ルール層が単独で最大の寄与**であり、この決定の妥当性の根拠になっている。
- 受け入れたトレードオフ: 「法人格も敬称も無く、辞書にも無い固有名詞」は
  既定構成では落ちる。これが残り 2.3% の主な中身。
- **見直し条件**: golden corpus に「手がかりのない未知固有名詞」のケースが増え、
  決定的層では原理的に届かない見逃しが recall 基準（≥ 95%）を割るようになった場合。
  その時点で NER の既定 on 化を再検討する（v0.2.0 以降の議題）。
