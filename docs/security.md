# Security model

脆弱性の報告手順は [`../SECURITY.md`](../SECURITY.md) にある（ここには重複させない）。
この文書は「namemask が何を守り、何を守らないか」を書く。

---

## What namemask protects

**「機密テキストがマシンから出ない」こと。** これが唯一の中心的な保証。

具体的には次を守る:

- 原文・mapping・トークンがネットワークへ出る経路を作らない（telemetry を含む）。
- 原文の断片がログ・例外メッセージ・成果物（wheel・テストフィクスチャ）に残らない。
- 保存された mapping が、同一ホストの他ユーザーから素朴に読めない。
- 復元が失敗したとき、それらしい値を捏造せず失敗として報告する。

## What namemask does NOT protect

**この節は機能の免責ではなく、安全性の一部である。** 利用者が namemask を
「自動的な境界（gate）」だと誤解した瞬間に、このツールは危険なものに変わる。
namemask は**レビューの補助（aid）**であり、人間がマスク結果を読んでから送る前提で
設計されている。

### 検出漏れは脆弱性ではない

namemask は recall 100% を主張していない（実測 97.7% / 99ケース。
[`accuracy.md`](./accuracy.md)）。検出漏れは**設計上あり得るもの**として扱い、
セキュリティ報告ではなく通常の issue（*Detection miss* テンプレート）で受ける。

なぜそう決めているか:

- **日本語の固有名詞に「完全な検出」は存在しない。** 分かち書きが無く、法人格も敬称も
  付かない社名・人名は表層の手がかりを持たない。100% を主張するツールは、
  主張した瞬間から嘘をつくことになる。
- **漏れを脆弱性として扱うと、期待値が壊れる。** 「脆弱性が無い＝漏れが無い」と読まれ、
  レビュー無しで送る運用を招く。それは namemask が最も避けたい事故そのもの。
- **代わりに数値で管理する。** recall は golden corpus で測り、CI の閾値ゲートで
  退行を止める。漏れの報告は corpus のケースになり、次のリリースで数値として改善される。
  **recall が下がる方向のケース追加も歓迎する**（課題が可視化されるため）。

したがって、報告してほしいのは「漏れたこと」ではなく「**漏れないはずの経路で漏れたこと**」
（辞書に載っている取引先が拾われない、正規表現対象のメールアドレスが素通りする、など
[受け入れ基準](./accuracy.md) を割る事象）である。

### マスク済みテキストは匿名化ではない

- **再識別は防げない。** 固有名詞を伏せても、案件の内容・日付・金額・文体から
  当事者が特定できることがある。プレースホルダの個数と配置自体も情報を持つ。
- **マスク済みなら外部AIに出してよい、とは限らない。** 「マスクしても外部に出せない」
  データ種別は存在する。対象データ種別の線引きは**組織のポリシーで事前に決める前提**で、
  namemask はその判断を代行しない。
- **外部AI側は制御できない。** 送った先での保存・学習・ログ化は namemask の管轄外。

### 対象範囲の限界

- 日本語のPIIパターンのみ。他言語は対象外。
- プレーンテキストのみ。画像・音声・PDF のレイアウトは扱わない。
- **過剰マスクは軽微な失敗として意図的に許容している**（recall 優先。
  [`adr/`](./adr/) の 0004）。過剰な部分はレビューで捨てられるが、漏れは捨てられない。

## Invariants

これを壊す変更は受け付けない。テストで担保する。

### Core

1. **可逆。** `unmask(mask(x))` で原文が完全復元される。
2. **失敗は非対称。** 検出漏れ＝漏洩（致命）、過剰マスク＝軽微。**recall 最優先。**
3. **完全ローカル。** 外部通信ゼロ（telemetry 含む）。モデル・辞書もローカル。
4. **決定的コア。** 同じ入力→同じ出力。エージェントの推論ループで駆動しない。
5. **LLM は追加専用の検証者。** 解除・変更は不可。落ちても決定的層によるマスクは残る。
6. **原文を書き換えない。** 正規化は影のコピー上、置換は原文座標に対して。
7. **生値を捏造しない。** 復元不能は未解決として報告する。

### Output and storage

8. **LLM エンドポイントはループバック限定**（`localhost` / `127.0.0.0/8` / `::1`）。
   非ループバック URL は既定で例外。`llm.allow_remote: true` が唯一の安全弁で、
   既定 true にしない。
9. **ログ・例外・レポートに原文断片を残さない。** NER の未マッピングラベル警告も
   ラベル名のみ。
10. **mapping は生の機密。** ライブラリAPIは既定メモリ内。CLI の保存は限定ディレクトリ・
    0o700/0o600・gitignore・stderr 警告。
11. **`--html` の出力も原文を含む。** 外部CDN・外部JSを参照しない自己完結HTMLを維持する。
12. **外部ツールの都合でコアを改修しない。**

## Threat model

### T1: Data egress via the tool itself

**このツール自体が漏洩源にならない**ことが最優先。ネットワークに触れ得る経路は
設計上2つしかなく、どちらも既定で無効か、ローカルに閉じている。

| 経路 | 既定 | 状態 |
|---|---|---|
| LLM 検証パス（Ollama） | **off**（`--llm` で明示的に有効化） | ループバック限定（T4） |
| NER モデルのロード（GiNZA） | off（extras・`--no-ner` で無効化） | **ローカルにインストール済みのモデルを読むだけ。namemask はモデルをダウンロードしない** |

- **telemetry を持たない。** 使用統計・クラッシュレポート・バージョンチェックの類を
  一切実装しない。
- **必須依存は `pyyaml` と `pyahocorasick` の2つだけ**で、どちらもネットワークを使わない。
  依存を増やす変更は、**その依存がネットワークを使わないことの説明**を伴う必要がある
  （[`../CONTRIBUTING.md`](../CONTRIBUTING.md) の Invariants）。
- **外部AIへの送信 API を持たない。** 送信は利用者が手でコピーする経路だけ。
  これは機能不足ではなく設計上の選択で、自動送信を実装すると「レビュー前に送る」経路が
  必ず生まれるため。マスクは 100% ではない以上、送信の直前に人間の目を構造的に挟む。

### T2: Raw text leaking into artifacts

原文が残り得る場所すべてに対策を置く。

- **ログ** — `logging` に出すのは例外の**型名**と、NER の未マッピング**ラベル名**だけ。
  本文・表層文字列は出さない。未マッピングラベルの警告はラベルごとに一度だけ出す。
- **例外メッセージ** — 原文断片を載せない。スパンの不整合など座標を含む例外はあるが、
  `Span` は座標と型しか持たない（表層文字列を保持しない）ため本文は漏れない。
- **検出根拠レポート** — 原文を含む。**人間のレビューのために端末（stderr）へ出す**もので、
  リダイレクトすればファイルに残る。レポート末尾は毎回「送る前にレビューすること」で
  終わる。
- **リポジトリと配布物** — テスト・ドキュメント・コミットメッセージに実在の
  人名・企業名・住所・電話番号・メールアドレスを入れない（**架空名のみ**）。
  取引先マスタ（`data/clients.csv` / `data/persons.csv`）と `.session/` / `*.mapping.json` は
  gitignore 済みで、CI の `secrets-guard` ジョブが**それらが追跡されていないこと**を毎回検査する。
  追跡するのは架空データの `data/clients.sample.csv` のみ。
  **辞書ファイルは配布物に同梱しない**（取引先マスタ自体が機密であり、同梱は全利用者への
  複製配布になる）。

### T3: The `--html` review page

生成される HTML は**原文と mapping 相当の情報を両方含む。** mapping ファイルと同じ機密度で
扱う必要がある。

- **外部参照ゼロを維持する。** CSS はインライン、JavaScript は使わない、外部CDN・
  外部フォント・外部画像を参照しない。原文を含むファイルが「開いただけで外部へ
  リクエストを飛ばす」ことがあってはならない。この性質を壊す変更は入れない（不変条件11）。
- **エスケープ** — 原文由来の文字列はすべて `html.escape()` を通す。原文に含まれる
  `<script>` 等がページ内で実行されない。ツールチップに入れる値も同様。
- **ページ冒頭に警告を出す** — 「送信前に必ず確認すること」「このファイルは原文を含むので
  外部に出さないこと」。CLI も生成時に stderr で同じ警告を出す。
- **`0600` で作成する。** 原文を含む以上、mapping と保護水準を揃える。出力先は利用者が
  任意に指定でき `/tmp` のような共有ディレクトリに置かれうるため、
  同一ホストの他ユーザから読める状態を既定にしない。既存ファイルへ上書きする場合も、
  緩いパーミッションを引き継がないよう作り直してから書く。
  POSIX で実効（Windows は ACL 管理下）。
- **既知の限界** — 保管場所の選択と、レビュー後の削除は利用者の責任。
  mapping と違い `--wipe` に相当する破棄手段は無い。

### T4: Non-loopback LLM endpoint

LLM 検証パスは**生のチャンクを POST する**ため、宛先の検証が漏洩の分かれ目になる。

- クライアント生成時にエンドポイントのホストを検査し、`localhost` またはループバック
  IP リテラル（`127.0.0.0/8` / `::1`）以外は**例外で拒否する**（接続を試みる前に落とす）。
- **ホスト名の DNS 解決はしない。** 解決自体が外部通信になり得るうえ、外部アドレスへ
  解決されるホスト名を通してしまう穴になる。文字どおりの `localhost` と IP リテラルのみを
  許可する。
- 唯一の迂回路は `config.yaml` の `llm.allow_remote: true`。**これを既定 true にしない。**
  既定値は事故が起きたときの被害範囲を決める。外部LLMへ送ることが業務上明示的に
  承認されている場合にだけ、利用者が自分で設定を書き換える。

### T5: Mapping file compromise

mapping は **token → 原文** の対応表であり、原文そのものと同等の機密。

- **保存するのは CLI だけ。** `mask` と `unmask` が別プロセスであるため保存が要る。
  ライブラリ API は戻り値に含めるだけでファイルに書かない。
- **保存先を限定する** — 既定は `app_data_dir()/.session/mapping.json`。cwd 相対の
  書き込みに依存しない（凍結ビルドで cwd が不定になり、意図しない場所に機密が
  書かれる事故を防ぐ）。
- **パーミッション** — ディレクトリ `0o700` / ファイル `0o600`。既存ファイルの緩い
  パーミッションを引き継がないよう削除してから `O_CREAT` に `0o600` を渡して作り直す。
  **Windows では POSIX パーミッションが実効しない**（ACL 制御が別途必要）という既知の
  制約がある。共用PCでの運用は `--encrypt` と併用する。
- **破棄** — `unmask --wipe` と `wipe` サブコマンド。保存時は stderr で警告し、破棄を促す。
  **既知の限界**: `wipe` はファイルの削除であり、ディスク上の残留（ジャーナリング・
  SSD のウェアレベリング）までは消せない。
- **暗号化**（`--encrypt`）— Fernet（AES128-CBC + HMAC-SHA256）で保存し、鍵は Scrypt で
  パスフレーズから導出する。**認証付き**なので改竄とパスフレーズ不一致は復号失敗として
  検知され、誤った平文を返さない。`cryptography` 未導入時は明確なエラーで停止し、
  **平文フォールバックはしない**（機密の意図せぬ平文保存を防ぐ）。
- **パスフレーズは環境変数 `NAMEMASK_PASSPHRASE` で渡す。** コマンドライン引数にしないのは、
  同一ホストの他プロセスからプロセス一覧で見えるため。

### T6: Incorrect restoration

**間違った復元は、静かな改竄である。** 復元できないことより、それらしい別の値に
戻ってしまうことの方が危険。

- mapping に対応の無いプレースホルダは**復元せずそのまま残し**、`unresolved` として
  報告する。CLI は未解決があれば終了コード 1 を返す（呼び出し側が検知できる）。
- 改変されたプレースホルダの寛容照合は**警告付きで**行う（黙って直さない）。
- 復号失敗（パスフレーズ不一致・改竄）は認証タグで検知して例外にする。推測復元しない。
- マスク時に、原文自身がプレースホルダ様の文字列を含む場合はその番号を飛ばす。
  復元時の二重置換と、原文由来の文字列の誤復元を同時に防ぐ。

## Operational assumptions

namemask が成立するために、**利用側が満たす必要がある**前提。

1. **マスク結果を人間が読んでから送る。** これが崩れると T1〜T6 の対策の意味が消える。
2. **外部AIに出してよいデータ種別を、組織が事前に線引きしている。**
   マスクは「出してよい」の判断を代行しない。
3. **辞書（取引先マスタ）を最新に保つ。** 辞書層の recall 100% は「辞書に載っている」
   ことが前提。新規取引先の追加が止まれば、その分だけ漏れが増える。
4. **mapping と `--html` の出力を、原文と同じ場所・同じ扱いで保管し、破棄する。**

## Out of the threat model

- ローカルでコード実行権限を持つ攻撃者（同一ユーザー）
- 第三者モデル（GiNZA / Ollama モデル）自体の脆弱性
- ホスト型サービスとしての運用（そもそも設計に含まない。不変条件3違反）
- **ローカルHTTPサーバーとデスクトップアプリ** — このパッケージに含まれない
  （[`adr/`](./adr/) の 0011）。別プロジェクトの担当。
